# CivVIToolkit v0.2.3 Preview

## Focus: stability with multiple trainer features enabled

- Adds a stability scheduler so enabled toggles are staggered, rate-limited, and serialized instead of writing the GameCore in one burst.
- Corrects the live Unit collection chunk range to `+0x98/+0xA0`, preventing invalid object writes when several unit-related features are enabled together.
- Creates the remote GameCore call bridge only for research, civics, production, resources, and other paths that actually require it, with cooldowns and duplicate-target suppression.
- One-turn research and civics no longer spam the same target at high frequency.
- One-turn production processes at most one city per scheduler pass to avoid re-entering a production queue while it is mutating.
- AI research / civic / production / resource operations rotate across AI players to reduce remote-thread and write bursts.
- Unit and city collections are snapshotted before writes so collection mutations do not leave the iterator on stale addresses.
- Direct Int32 writes occur only when the value actually differs, reducing unnecessary memory traffic.
- If one enabled feature fails, only that feature is removed from background enforcement; other enabled features remain active.
- The SHA-256 fingerprint gate and all 13 AoB anchors for Steam / DX12 / Gathering Storm 1.0.12.68 (1023995) remain mandatory.

## Suggested acceptance

Start with `Num 1 + Num 2 + Num 6 + Num 7 + PageDown` enabled together for several minutes, then add city, resource, and AI features gradually. Add remote-call-heavy features last.
